# AI-tell edits

Rewrite at the sentence level. The goal is not to make the text rougher; it is to remove the tells that make it sound like a generic model wrote it.

## False-profound opening

Before:

> 从一张看不见的待办便签开始，我试着把“软件该长什么样”交给工具决定。

After:

> 前阵子我老在跟 AI 聊天。聊着聊着，就会留下一些“回头再说”的事。

The second version starts with a scene. The first starts with a thesis about the scene.

## Repeated "不是……而是……"

Before:

> 这不是一个效率问题，而是一个信任问题。

After:

> 我担心的不是效率。出了问题谁负责，这个更麻烦。

One inversion is fine. Three in four paragraphs becomes a tic.

## Essay transitions

Strong defaults:

- delete "换句话说" and "这让我想到"
- delete "更重要的是" when it only announces emphasis
- keep "当然", "或许", and "某种程度上" only when they carry a real qualification

Often the next sentence already does the work. If it does not, write the missing fact.

## Over-symmetry

Before:

> 它足够灵活，但也有清晰的边界。

After:

> 它能跑，但跑不快。

Not every paragraph needs a balanced pair. Plain subject-verb-object is usually enough.

## Abstract summary

Before:

> 这本质上是一次把选择权交还给使用者的实践。

After:

> 你不用先学一套新规则，直接说你要什么就行。

Replace the summary with the thing the reader can do or see.

## Launch-deck English

Replace:

- "The original problem was mundane" → "I kept running into a small, annoying thing."
- "Technical bits" → delete the heading and start with the first detail.
- "Current limitations" → "What's still rough"
- "The obvious comparison is ..." → "People will ask about ..."
- "I'd love to hear ..." → "Curious what ..."

## Closing summary

For a personal essay: if the last paragraph only repeats the article, delete it. A better ending is a concrete next step, a real uncertainty, or a line the author would actually say.

For a technical explainer or list: a short summary is allowed. Keep it factual and skip the uplift.
